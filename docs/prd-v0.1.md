# FunMedal 产品需求

本文是 PRD（产品需求文档：写清做什么、为什么做、给谁用、做哪些、不做哪些）。产品的愿景和定位在仓库根目录的 [MISSION.md](../MISSION.md)，本文只写具体的用户需求，两者不合并（项目负责人 2026-10-24 的决定）。

2026-10-18 起，项目负责人决定用 Document Governance（一套管理项目文档的规则，文档都放在 `docs/` 下）管理项目文档，并逐条重新审视现有需求。下面各节在 2026-10-24 的八轮访谈里一条条填写完毕，角色和声音的细节也在同一天看过效果图、听过样音后定了。

## Goals

- 卡片只做一件事：显示 Claude Code（Anthropic 公司的 AI 编程助手，在电脑上运行）当前所有在跑任务的状态。项目负责人 2026-10-24 原话：

  > 这个卡片只需要做一件事：显示 Claude Code 当前所有在跑任务的状态。比如我的 Claude Code 现在有三个不同的项目正在跑，每个项目里都开了一个 thread 在开发。我希望这个卡片最大的价值就是，我拿起卡片，或者我电脑在看 YouTube 时，通过手边卡片的小屏幕就能看到：1. 目前这三个项目正在跑还是已经停了；2. 有没有需要我介入或输入的地方。

- 到 2026-10-24 为止，项目负责人自己还没有真正用起来这张卡片（第一轮访谈 Q1 答“还没怎么用起来”）。所以本文里的需求都是设想，要靠负责人实际使用来验证；哪条需求被实际使用推翻了，就在这里改。

## Target Users

- 近期：项目负责人自己。
- 长期：做成产品出售（项目负责人 2026-10-24 的决定）。目标用户和 MISSION.md 一致：用 Claude Code 做软件开发的程序员、软件工程师、硬件工程师和 AI 工程师，尤其是同时开着多个项目、多个会话的人。

## Scope

用词按 [SOURCE: docs/domain/glossary.md]：项目是 Claude Code 打开的一个代码目录，会话是项目里的一段对话（桌面 App 里的 thread）。

- Included:
  - 同时显示所有正在跑的会话，按项目区分，一行一个会话，不再像现在只汇总成一种状态。
  - 每个会话显示四种状态之一：在跑、等你、答完了、出错。定义见术语表。
  - 一眼看得出有没有会话在“等你”。
  - 屏幕外观有几套主题（见术语表），用户可以自由切换，显示的信息不随主题变。
- Excluded:
  - 在卡片上批准或拒绝。2026-10-24 从范围里拿掉，想法存在 [SOURCE: docs/ideas/IDEA-20261024-001-card-approve-deny.md]。要处理的事去电脑或手机上处理。
  - 按住说话。2026-10-24 拿掉，想法存在 [SOURCE: docs/ideas/IDEA-20261024-002-push-to-talk.md]。
  - MISSION.md 里“现在已经有的，不重复做”一节列出的事。
  - 原来的像素小人：由以负责人女儿为原型的角色替代，见 Business Rules。

## Business Rules

- 一行一个会话，每行写项目名、状态词，“答完了”的再写答完多久。项目名就是 Claude Code 打开的目录名，因为桥接程序拿不到会话标题。会话在上一级文件夹启动、在里面某个仓库干活时（比如 claude.ai 项目派到这台 Mac 上的会话），项目名是它正在干活的那个仓库：从 hook 送来的当前目录往上找最近的 `.git`，最远找到启动的文件夹；找不到时仍用启动的文件夹名。在仓库根目录启动的普通会话名字不变。负责人 2026-10-25 的原话：“两种情况都出方案给我看：助手会话的项目名、被打断后停在“在跑”。先别动代码。”看过方案后说：“方案可以，三件都按这个做”。同一个项目开了两个会话就显示两行一样的项目名，不加编号、不加标题：看一眼要知道的是“这个项目有一个在等我”，是哪个会话去电脑上看（负责人 2026-10-24 看效果图后选定）。
- 会话关掉后从卡片上消失。
- 行的顺序按要不要你处理排：等你 → 出错 → 在跑 → 答完了。同一状态里，“等你”和“出错”是等得最久的在上，新来的接在这一组最后，已经在屏幕上的行不动；“在跑”是开始得早的在上；“答完了”是刚答完的在上，放不下时先挤掉答完最久的。这里的“等得最久”“开始得早”“刚答完”都按这一行最近一次换状态的时间算。不再按项目名排，同一项目的几行不一定挨在一起。负责人 2026-10-26 被问到“按字母顺序还是别的”时的原话：“不按字母顺序，按优先级高低排”；看过效果图后，对“等得最久的在上，新来的接在后面，已经在屏幕上的行不动”答“同意”。
- 卡片最多显示 6 行。超过 6 个会话时按上面的顺序只显示前 6 个，不翻页；“等你”加“出错”的会话不超过 5 个时，被挤掉的一定是“在跑”或“答完了”的（项目负责人 2026-10-24 确认）。
- “等你”加“出错”的会话超过 5 个时，同一项目、同一状态的几个会话合成一行，状态词后面写“×N”（N 是这一行代表几个会话；漫画分格写在项目名后面），这一行排在其中等得最久的那个会话的位置。合成以后仍有“等你”或“出错”的会话没显示出来时，顶栏把“+N”换成“还有 N 个等你”（N 是没显示出来的“等你”和“出错”会话数）；没显示出来的只有“在跑”或“答完了”时，仍写“+N”。新变成“等你”或“出错”的会话即使放不下，也照常提醒：桥接程序在提醒那一刻把它放进发给卡片的 6 行里，提醒过后它回到按顺序该在的位置。“×N”由卡片固件来画，蓝牙数据里每行带“几个会话”的数，顶部带“等你和出错一共几个”。连着来两个提醒时，提示音再响一次。负责人 2026-10-26 被问到这种情况时的原话：“这种问题的处理也要做到最好，给出最佳方案”；看过效果图后，对合并答“同项目同状态合成一行，写 ×N”，对顶栏“还有 N 个等你”答“同意”，对卡片固件画“×N”、蓝牙版本号从 4 改成 5 答“同意”，对连着两个提醒答“再响一次”。
- 角色在每套主题里都要全身露出来，不能被底栏或格子边切掉，也不能压住任何一个会话。漫画分格和控制塔这两套按格子排的主题，第 6 格固定留给角色，最多显示 5 个会话；超过 5 个时按上面的顺序只显示前 5 个，顶栏的“+N”或“还有 N 个等你”算上没显示的那些。负责人 2026-10-25 原话：“其他主题也一样，我女儿要给足够的空间，如果遮拦到了其他会话，那就不现实那个会话也要给我女儿 留出空间”。游戏任务板和街机厅按行排，角色在底栏里，仍显示 6 行。
- 空出来的地方多时，角色跟着变大：会话越少她越大，最小是默认大小（64 × 74 像素），变大后仍然不压住任何会话和提示字。只有一处例外，是负责人 2026-10-25 看过对比图后选定的：街机厅在 1、2 个会话、她长到 200 像素高时，她的胳膊会盖住左下角装饰文字“INSERT COIN”的最后一个字母，不改（记录在 `notes/firmware.md` 的“角色”一节）。大小分四档，高 74、112、145、200 像素，卡片挑放得下的最大一档；会话数一变，下一帧就换成新大小。漫画分格和控制塔会把空着的整行格子连同第 6 格合成一个大格子给她住。负责人 2026-10-25 原话：“我我可以再增加一个需求吗？就是我感觉我女儿现在的呃太小了，呃，我我我的意思是，如果任务比较少的话，比如说只有两个的话，下面的空间不是会空的很大吗？空的很大的情况下，那就它就变得大一点，懂我意思吗？然后，如果达到了五个的时候，那么它就是默认大小，就是它至少是默认大小。然后呢，根据这个屏幕空出来的这个情况，然后它自己会变大，动态的。”四档大小、合成大格子和直接换大小是负责人看效果图后选的。
- “等你”不区分权限请求、选择题、计划确认和下一步框里的问题（下一步框是 Claude Code 电脑端在一轮结束时显示的小结框，里面可以带一个问题和几个按钮），因为这几种都要去电脑或手机上处理，区分对用户没有用。负责人 2026-10-25 的原话：“两种都算“等你”：选择题弹出时、下一步框里带问题时。先实测桥接程序在这两种情况下收到哪些事件，再写方案给我看。”实测后定下：下一步框带问题时，这一行显示“等你”，直到你回复；Mac 只告诉卡片“有没有问题”，不传问题和小结的内容。
- 会话其实已经停下，桥接程序却没收到对应的 hook 事件时（比如生成回答时按 Esc 打断，或者桥接程序停着的那段时间里会话弹出了批准框），这一行不能一直停在“在跑”。桥接程序每 15 秒在后台问一次 Claude Code 自带的 `claude agents --json`（它列出这台 Mac 上每个会话是在忙、在等人还是闲着）：说“在等人”而这一行不是“等你”时，改成“等你”并照常提醒；连续两次说“闲着”时，“在跑”改成“答完了”；连续两次说“在忙”或“闲着”时，去掉 hook 没有在等的“等你”记录，下一步框里的问题除外。说“在忙”、只说一次“闲着”、核对期间这个会话又送来 hook 事件、列表里没有这个会话、命令运行失败或读不懂时，都不改。负责人 2026-10-25 的原话：“两种情况都出方案给我看：助手会话的项目名、被打断后停在“在跑”。先别动代码。”看过方案后说：“方案可以，三件都按这个做，先做停在“在跑”那件，审查后提交推送。”
- Claude Code 项目（几个 thread 归在一个项目里，由项目的协调会话把任务转给各个 thread）里派出来的 thread，卡片上名字前画一个醒目的橙色 P 贴纸（橙色底、白圈、黑边、右下黑影，粗体白色 P），普通本地 thread 没有；四套主题都画。判断办法：会话收到的某条消息以 `<relay from="coordinator"` 开头（协调会话转来的消息就是这样开头的），这个会话就算项目 thread，之后一直算，直到会话关掉。Mac 只告诉卡片“是不是项目 thread”，不传消息内容。负责人 2026-10-25 的原话：“你现在知道最新版的claude里面有projects的功能吗？如果你不知道请搜索最新信息。 这个也要能在卡片展示出来。不然我不知道这个人物是一个普通的本地thread还是projcets里面的一个thread”。看过两套 P 图标样图后选了“B 橙色贴纸”。
- “答完了”的会话一直显示，直到会话关掉，旁边写上答完了多久（比如“2 小时前”）（负责人 2026-10-24 选定）。
- Mac 和卡片断开时整屏显示“未连接”；一个会话都没有时显示“没有会话”（2026-10-24 提出，负责人没有异议）。
- 有会话进入“等你”或“出错”时，卡片要主动提醒：一个以负责人女儿为原型的角色冒出来，配一句话，比如“爸爸快看一下，需要你去做决定”“爸爸快看一下，出问题了”，同时用喇叭出声（负责人 2026-10-24 提出）。
- 角色用真人形象：负责人用图像生成工具、以女儿的照片为参考生成的写实全身图，不是卡通（负责人 2026-10-24 看过三种做法的效果图后选定；另两种是纯卡通和真人头配卡通身，不做）。分工：Claude 写每个动作的提示词，负责人用同一个工具、以第一张设定图为参考图生成各个动作，Claude 负责抠掉白底、裁切、缩到卡片尺寸和上屏。第一版要的动作列表在 `private-assets/角色生成提示词.md`。
- 角色不只在提醒时出现，平时也一直在屏幕上，是个生动活泼的小精灵（负责人 2026-10-24 第六轮提出）。第一版十个动作和用法，负责人 2026-10-24 看过动画效果图后认可：
  - 平时（没有会话在等你或出错）她在屏幕角落循环做小动作：趴着发呆 5 秒 → 拍桌子三下（举起、拍下两张图交替）→ 歪头、旁边弹出一个问号 3 秒 → 自言自语、旁边弹出一个小气泡 3 秒 → 趴着打瞌睡、旁边飘 zZ 5 秒 → 回到发呆。各段时长在设计时可调。
  - 有会话进入“等你”：她从提醒卡片底边冒出来、举手喊，配文字“爸爸快看一下，需要你去做决定”和提示音。进入“出错”：捂脸着急，配“爸爸快看一下，出问题了”和提示音。
  - 卡片刚连上 Mac：她挥手，配“连上了”。一个会话答完了：屏幕底部弹出小条，她在旁边欢呼，3 秒后收起。
  - 问号、气泡、zZ 不画在图里，由屏幕单独画，所以能单独弹出和消失。
  - 十张图由负责人用图像生成工具按 `private-assets/角色生成提示词.md` 生成，Claude 切图抠白底后存在 `private-assets/character/real/`，不进仓库。产品版换成默认素材包。
  角色替代原来的像素小人。
- 声音：不放真人说话声，只放一段提示音，免得突然吓到别人。负责人 2026-10-26 的原话：“我我我改一个需求，不要不要放出那种真人说话声音，而是用一个提示音，不然会突然吓到别人。”听过三组样音后，负责人 2026-10-26 选了“B 叮咚；删掉，卡片直接合成”：进入“等你”放两声往上走的“叮咚”（G5 784 Hz 接 C6 1046.5 Hz），进入“出错”放两声往下走的（C6 接 G5）；声音由卡片自己现算，固件里不放声音文件，用合成童声念那两句话的做法整个删掉。这一条取代 2026-10-24 定的“用女儿本人的声音说那两句话”，以及 2026-10-26 定的“第一版先不放笑声，只念那句话”。素材包里只有角色图，没有声音。
- 负责人女儿的照片、生成的形象、录音放在仓库根目录的 `private-assets/` 下，这个目录写进 `.gitignore`（告诉 Git 不要跟踪的清单），和 `firmware-backup/` 一样只留在负责人本机，不进公开仓库。
- 屏幕：USB 接着电脑时常亮；只用电池时 5 分钟没有变化就熄屏（负责人 2026-10-24 选定）。只接充电器、不接电脑时按电池处理，也会熄屏（负责人 2026-10-24 在设计阶段确认，因为固件只能可靠判断“接着电脑”）。熄屏后有会话进入“等你”或“出错”时，屏幕亮起来、角色冒头、喇叭出声，之后再按 5 分钟没变化熄屏（负责人 2026-10-24 选定）。
- 主题：第一版做四套，用户自由切换，不是只选一套（负责人 2026-10-24 看过三轮效果图后的决定，原话“不是一定要从里面单选一个来做，而是都要，供我自由切换主题”）。四套是：
  - 游戏任务板：粗线条圆角大色块，“等你”的那条在呼吸，“在跑”的条上有流动的斜纹。效果图在 [notes/mockups/2026-10-24-lively.html](../notes/mockups/2026-10-24-lively.html) 的“游戏任务板”一节。角色平时在右下角；提醒是一张圆角卡片，她从卡片底边冒出来。
  - 街机厅：黑底绿字加扫描线，像素字体，“等你”的那行像老街机“PRESS START”那样闪。效果图在 [notes/mockups/2026-10-24-game.html](../notes/mockups/2026-10-24-game.html) 的 A 节。角色平时在右下角，“INSERT COIN”挪到左下；提醒是黄色双线框卡片（出错时红色），她在卡片左边。扫描线不盖在角色身上，只盖屏幕和文字（负责人 2026-10-24 看效果图后要求）。
  - 漫画分格：每个会话一格漫画，用拟声词当状态（“哒哒哒”在跑、“！！”等你、“啊！”出错、“呼～”答完了），有事时角色从纸上撞出来。同一文件的 D 节。角色平时住在最后一格里，这一格不让给会话（见 Business Rules 的 5 个会话上限）。提醒是黄色爆炸星（出错时红色），她和大字一起撞出来。
  - 控制塔：深蓝驾驶舱，每个会话一个带指示灯的模块，灯的动法就是状态（雷达转是在跑、黄灯呼吸是等你、红灯急闪是出错、绿灯常亮是答完了）。同一文件的 E 节。角色是驾驶舱里的值班员，平时占最后一个模块（同样不让给会话）；提醒时整屏泛黄光（出错时红光），她从一张发光边框的实心卡片里冒出来。

  四套里角色的放法负责人 2026-10-24 看效果图后都认可，效果图在 `private-assets/review/`，不进仓库。主题只改画法，不改信息：每套都显示同样的会话、同样的四种状态和“答完了”的时间，角色提醒在每套里都有。同一批效果图里没被选的（规整版三种、像素工位、便签墙、小岛、RPG 队伍）不做。
  - 在卡片上按一个键轮着换主题，Mac 这边不用管；具体用哪个键在设计时定（负责人 2026-10-24 选定）。
  - 默认主题是游戏任务板：第一次开机和恢复出厂时显示它（负责人 2026-10-24 选定）。
- 配套功能全部保留：安装和卸载脚本、doctor 自检、固件和桥接程序互报版本、蓝牙配对加密、预编译固件刷写、原厂固件备份恢复、开源发布（负责人 2026-10-24 选定）。

## Acceptance Boundaries

负责人 2026-10-24 第八轮确认。分两层：第一层是功能检查，除第 4 条外每条都要能当着负责人演示；第二层是真实使用，因为本文的需求都是设想，要靠实际使用验证。

第一层，功能检查：

1. 开三个项目、每个一个会话，卡片在 3 秒内显示三行，项目名和状态都对。
2. 同一个项目开第二个会话，卡片多出一行同名的；关掉一个会话，那行在 3 秒内消失。
3. 一个会话进入“等你”，3 秒内那行跳到最上面变“等你”，角色冒头说话，喇叭响。“出错”同样提醒，排在“等你”之后、“在跑”之前。
4. 开 7 个会话，卡片只显示 6 行（漫画分格和控制塔只显示 5 个，第 6 格是角色），被挤掉的是“在跑”或“答完了”的；“等你”加“出错”超过 5 个时，同项目同状态合成一行写“×N”，还放不下时顶栏写“还有 N 个等你”，放不下的新“等你”照常提醒。这一条不演示，自动测试通过就算（负责人 2026-10-24 决定）。
5. “答完了”的行显示答完多久，过一小时后数字跟着变。
6. 按卡片上的键能在四套主题之间轮着切；断电重启后还是上次选的那套；第一次开机是游戏任务板。
7. 只用电池放 5 分钟，屏幕熄灭；这时来一个“等你”，屏幕亮起、角色冒头、有声音。为了演示，测试时允许把 5 分钟改短。
8. 关掉 Mac 上的桥接程序，卡片显示“未连接”；桥接程序开着但一个会话都没有，显示“没有会话”。
9. 卡片上没有任何键能批准或拒绝 Claude 的请求。
10. 角色平时在屏幕上有动作，不是一张静止的图。
