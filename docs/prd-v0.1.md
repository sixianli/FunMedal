# FunMedal 产品需求

本文是 PRD（产品需求文档：写清做什么、为什么做、给谁用、做哪些、不做哪些）。产品的愿景和定位在仓库根目录的 [MISSION.md](../MISSION.md)，本文只写具体的用户需求，两者不合并（项目负责人 2026-10-24 的决定）。

2026-10-18 起，项目负责人决定用 Document Governance（一套管理项目文档的规则，文档都放在 `docs/` 下）管理项目文档，并逐条重新审视现有需求。下面各节在审视过程中一条条填写；写着“待审”的地方还没有讨论到，不代表已经决定。

## Goals

- 卡片只做一件事：显示 Claude Code（Anthropic 公司的 AI 编程助手，在电脑上运行）当前所有在跑任务的状态。项目负责人 2026-10-24 原话：

  > 这个卡片只需要做一件事：显示 Claude Code 当前所有在跑任务的状态。比如我的 Claude Code 现在有三个不同的项目正在跑，每个项目里都开了一个 thread 在开发。我希望这个卡片最大的价值就是，我拿起卡片，或者我电脑在看 YouTube 时，通过手边卡片的小屏幕就能看到：1. 目前这三个项目正在跑还是已经停了；2. 有没有需要我介入或输入的地方。

- 到 2026-10-24 为止，项目负责人自己还没有真正用起来这张卡片（第一轮访谈 Q1 答“还没怎么用起来”）。所以本文里的需求都是设想，要靠负责人实际使用来验证；哪条需求被实际使用推翻了，就在这里改。

## Target Users

- 近期：项目负责人自己。
- 长期：做成产品出售（项目负责人 2026-10-24 的决定）。目标用户和 MISSION.md 一致：用 Claude Code 做软件开发的程序员、软件工程师、硬件工程师和 AI 工程师，尤其是同时开着多个项目、多个会话的人。

## Scope

用词按 [SOURCE: docs/domain/glossary.md]：项目是 Claude Code 打开的一个代码目录，会话是项目里的一段对话（桌面 App 里的 thread）。

- Included:
  - 同时显示所有正在跑的会话，按项目区分，一行一个会话，不再像现在只汇总成一种状态。
  - 每个会话显示四种状态之一：在跑、等你、答完了、出错。定义见术语表。
  - 一眼看得出有没有会话在“等你”。
- Excluded:
  - 在卡片上批准或拒绝。2026-10-24 从范围里拿掉，想法存在 [SOURCE: docs/ideas/IDEA-20261024-001-card-approve-deny.md]。要处理的事去电脑或手机上处理。
  - 按住说话。2026-10-24 拿掉，想法存在 [SOURCE: docs/ideas/IDEA-20261024-002-push-to-talk.md]。
  - MISSION.md 里“现在已经有的，不重复做”一节列出的事。
  - 像素小人、doctor 自检、固件和桥接程序互报版本、配对加密、安装和卸载流程、预编译固件、原厂固件恢复、开源发布：待审（第三轮）。

## Business Rules

- 一行一个会话。同一个项目开了两个会话就显示两行。
- 会话关掉后从卡片上消失。
- 卡片最多显示 6 行。超过 6 个会话时只显示最急的 6 个，不翻页（项目负责人 2026-10-24 确认）。“最急”的顺序：待审（第三轮）。
- “等你”不区分权限请求、选择题、计划确认，因为三种都要去电脑或手机上处理，区分对用户没有用。
