## 意外和发现

- 2026-10-16 卡片闲置 5 分钟后进入深度睡眠，USB 串口随之消失；按键唤醒后恢复。读写 Flash 前要先确认串口存在。
- 2026-10-16 备份时 esptool verify-flash 报告 “Verification successful (digest matched)”，SHA-256 为 03d6dfc6…29db。
- 2026-10-16 本机终端的 claude 是 Homebrew 装的 2.1.116，没有 claude agents --json；文档最新是 2.1.301。
- 2026-10-16 打开卡片的 USB 串口会让它重启一次。
- 2026-10-16 ESP-IDF 在 macOS 上不自带 cmake 和 ninja，用 idf_tools.py 补装到 ~/esp/.espressif（约 240 MB）。
- 2026-10-16 从 Claude 里直接运行用蓝牙的命令行程序会被 macOS 结束：系统把它算在负责进程 claude 名下，而 claude 没有声明蓝牙用途（崩溃报告 namespace TCC）。测速程序改成独立 .app，由用户用 open 启动。Mac 端常驻程序也必须是独立 App。
- 2026-10-16 桌面 App 里的 Claude Code 是 2.1.295（~/Library/Application Support/Claude/claude-code/2.1.295/），终端是 Homebrew 的 2.1.116；桌面 App 会运行 ~/.claude/settings.json 里的 hooks（本会话压缩后触发了其中的 SessionStart hook）。
- 2026-10-16 终端 claude 2.1.116 登录已失效：测试会话发消息后报 401 “OAuth access token is invalid”，FM-8 需要用户先在终端登录。
- 2026-10-16 FM-11 实测：卡片到 Mac 最慢 309 kbps、Mac 到卡片最慢 253 kbps，5,934 个包没有丢失，来回一趟中位数 22 ms；macOS 默认连接间隔就是 15 ms（详见 notes/ble-link.md）。
- 2026-10-16 USB 串口截图约一成少数据：ESP-IDF v5.5.5 的 printf 串口输出（usb_serial_jtag_vfs.c 的 usbjtag_tx_char_via_driver）发送缓冲区满 50 ms 后会悄悄丢字符。改成整行交给驱动、等到有空位再写之后，90 张截图全部完整（详见 notes/firmware.md）。修之前是什么让发送停住 50 ms 以上，没有查实。
- 2026-10-16 三个功能键实测电压：不按 2897 mV，上 0–5，中 295–304，下 590–599（详见 notes/hardware.md）。
- 2026-10-16 FM-8 实测（终端 2.1.292）：PermissionRequest hook 和终端弹窗同时出现，先答的算数；终端先答时 hook 进程不会被结束，hook 之后的回答被忽略；用户全局设置的沙箱开着自动运行时，沙箱里的命令不弹窗（详见 notes/claude-code.md）。这说明“离开开关”可能不需要，要用户决定。
- 2026-10-16 Channels 实测（终端 2.1.292）：推消息进会话、经卡片批准或拒绝权限都成立；但每次启动都要加开发用的启动参数，并在警告对话框里确认一次；终端先回答权限时，Channels 服务端收不到任何通知（详见 notes/claude-code.md）。
- 2026-10-16 代码审核发现：卡片主动报的行（STATE、KEY、ADC）原来也最多等 2 秒，没人读串口时按键任务因此停了约 2 秒（key_gap_ms 2020）；改成发不出去就整行丢掉后为 10。macOS 替程序存下约 290 万字节的串口数据后就不再收。
- 2026-10-16 串口堵住时，排队的 16 条截图命令只回来 13 个结尾：卡片 16 条都执行了，但有 3 条的第一行和之后的 ERR 都在 2 秒内发不出去，什么也没回。加了 replies_dropped 计数后，13 + 3 = 16 对上了。
- 2026-10-16 自制固件下打开 USB 串口不会让卡片重启（连开 3 次，计数一直往上加，没有 READY），和原厂固件不同，原因没有查。
- 2026-10-16 longtask.py 找带标签的测试文件时，凡路径里有一层叫 tests 的文件都算，不看 fingerprint.exclude；所以测试结果不能放在 tests/ 下面。

## 决定

- 2026-10-16 目标用户的硬件先按“同款 TRAE 卡片”考虑；用户没有明确回答这一点，后续如有不同再改。
- 2026-10-16 原厂备份放在 firmware-backup/，不进 git：其中含这块板子独有的身份和配对数据。
- 2026-10-16 交互方案定为 A 像素小伙伴（G7）。
- 2026-10-16 iPhone 通知先走 ANCS；Mac 通知后做，用辅助功能接口读横幅；欧盟通知转发不做。
- 2026-10-16 原厂功能只要求能刷回（G9），不做双系统切换。
- 2026-10-16 麦克风由用户确认存在（G8）。
- 2026-10-16 语音进入第一阶段（G15），因此 Channels 也在第一阶段接入。
- 2026-10-16 Mac 端程序用 Swift：蓝牙、离线语音转文字、辅助功能接口都是 macOS 原生接口，编译后无需另装运行环境。
- 2026-10-16 语音压成 ADPCM（64 kbps）走蓝牙，不用 Wi-Fi；按键也走蓝牙。依据是 FM-11 实测卡片到 Mac 最慢 309 kbps。
- 2026-10-16 卡片固件第一版不含蓝牙，蓝牙外设和 Mac 端放在 FM-13 一起做：FM-12 先把屏幕、按键和串口测试入口做稳。
- 2026-10-16 卡片串口上的协议输出（OK、ERR、STATE、KEY、ADC、截图）一律整行写给 USB 串口驱动（console_printf），不用 printf。
- 2026-10-16 最上面的功能键在自制固件里当确认键，按用户在 G11 的安排。
- 2026-10-16 测试结果目录 tests/artifacts/ 不计入代码指纹（items.json 的 fingerprint.exclude）；完整串口记录 serial.full.log 只留本机，不进 git。
- 2026-10-16 卡片串口输出分两种（取代上面“协议输出一律经 console_printf”那条）：回复（OK、ERR、截图）一行最多等 2 秒，没发出去的记进 replies_dropped；主动报的行（READY、STATE、KEY、ADC）只等 5 ms，发不出去就整行丢掉，记进 events_dropped。依据：没人读串口时按键任务不能停。
- 2026-10-16 测试结果目录改为项目根目录的 artifacts/（取代上面 tests/artifacts/ 那条），仍不计入代码指纹；完整串口记录 serial.full.log 仍只留本机。
