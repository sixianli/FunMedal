# 上手方案讨论

本文记录 2026-10-17 的一次方案讨论：用户拿到卡片后，怎样少做操作、很快用上 FunMedal。参加讨论的是 Claude 和 OpenCode（另一个 AI 编程工具，这次用的模型是 `opencode/deepseek-v4.1-flash-free`，推理级别 `high`），一共两轮。这次只讨论方案，没有改代码。之后又和 OpenCode 里三个免费模型做了一轮头脑风暴，推荐组合有修改，见文末“多模型头脑风暴”。负责人审阅后，按 `.agents/tasks/onboarding/goal.md` 的 G14、G15、G17 改了相关段落。

起因是项目负责人的三段原话，见 `.agents/tasks/onboarding/goal.md` 的 G1–G3：现在要敲命令启动，不优雅；做成插件或 Skill 会不会更好；除了插件，还有没有让用户少操作、快上手的办法。

## 讨论结果

### 结论

1. **Claude Code 这一侧，插件仍然是最好的装法。** 插件是 Claude Code 的扩展包，可以用一条命令装好。双方意见一致。Skill（教 Claude 做某件事的说明文件）不合适：它只在 Claude 决定用它时起作用，不会在会话开始时自己运行，也不能在后台一直运行，所以没法自动启动桥接程序（Mac 上把 Claude Code 和卡片连起来的程序）。
2. **“比只做插件更好”的改进，在插件之外的三处：**
   - 语音不再要求用开发参数（自己写的频道必须加的一个启动参数）启动 Claude Code：把语音入口从“频道”（Claude Code 把外部消息推进会话的接口）换成插件里的 mod（插件里一段在 Claude Code 内部运行的 JavaScript，详见下文）。
   - 桥接程序不再要每次开机手动启动：使用者自己编译一次，装在固定位置，由插件在会话开始时自动启动。负责人 2026-10-17 定不发编译好的 App，开源以后也由使用者自己编译（G14）。
   - 刷固件不必装 ESP-IDF（乐鑫官方的芯片开发工具，几 GB）：发编译好的固件文件，只装 `esptool`（乐鑫的刷写工具，一个小 Python 包）就能刷；想自己编译的人照旧用 ESP-IDF（负责人 2026-10-17 定，G15）。网页方式以后再定。
3. **按推荐做完后，每天的操作是 0 步**：打开 Claude Code，卡片的状态显示、按键批准、按住说话就都能用。一次性的操作从现在的 7 步（要装几 GB 的工具），降到“把 Claude Code 升级到最新版、编译并安装桥接程序（要装 Xcode 命令行工具，Apple 免费提供的编译工具）、跑两条命令装插件、刷固件、配对、允许蓝牙和语音识别各一次”。这是按文档推算的，还没实测。
4. **最大的不确定点曾是 mod 能不能真的代替频道。** 讨论后在终端里做了实验，结论是能，见下文“mod 实验”一节。桌面 App 里平常的情况也能，但按过 Stop 之后 mod 送的话会被丢掉，见“桌面 App 里的 mod 实验”。复查查明这是 Claude Code 引擎自己的规则，用户在电脑上亲手打一句话就恢复，见“按 Stop 之后丢话的复查”。

### 现在最费事的地方

按 `README.md` 的 7 个安装步骤：

| 步骤 | 用户现在要做的 | 一次性还是反复 |
| --- | --- | --- |
| 1 备份、2 刷固件 | 装 ESP-IDF（乐鑫官方的芯片开发工具，几 GB）；每开一个新终端先运行 `export.sh`；用 `idf.py build flash` 编译并刷进卡片 | 一次性，但最重 |
| 3 桥接程序 | 装 Xcode 命令行工具，`sh build.sh` 编译，再用 `open -g … --args serve` 启动 | 每次开机都要再启动；每次重新编译后都要重新允许蓝牙 |
| 4 配对 | Mac 上点连接，卡片上按键 | 一次性，已经够简单 |
| 5 语音授权 | 敲一条命令弹出语音识别授权框 | 一次性，重新编译后再来一次 |
| 6 hooks | 往 `~/.claude/settings.json` 手工粘 9 段 hooks（Claude Code 在特定时刻自动运行的命令，比如要你批准时） | 一次性，容易粘错 |
| 7 频道 | 写 `mcp.json`；每次要用语音，都用一长串参数启动 `claude`，还要在警告里选同意 | 每天 |

第 7 步的“频道”（channel）是 Claude Code 的一种扩展接口，能把外部消息推进会话，FunMedal 用它把语音转成的文字送进会话。自己写的频道不在官方允许名单里，必须带开发参数 `--dangerously-load-development-channels` 启动 Claude Code 才会加载。

双方都认为最费事的三处是：第 1、2 步的 ESP-IDF；第 7 步每天带开发参数启动；第 3、5、6 步的手工粘配置、重新编译后重新授权、每次开机手动启动。

| 2 | 插件里加 mod，语音改由 mod 送进会话，代替频道 | Claude 第一轮；OpenCode 第一轮没想到，第二轮同意，并补了 6 条风险 | 推荐，但要先做实验 |
| 3 | 安装脚本把 9 段 hooks 合并进 `settings.json`，再加一个 `fmclaude` 短命令代替长启动命令 | OpenCode 第一轮 | OpenCode 第二轮自己放弃：插件已能一条命令装好；卸载、升级、和用户已有 hooks 共存，脚本都不如插件干净 |

方案 2 的 mod 是插件里的一段 JavaScript，在 Claude Code 内部运行。它能在会话开始时做事、定时做事、启动并读取一个一直运行的小程序，还能用 `$.prompt.submit({ text, asUser: true })` 把一段文字当作用户自己打的字送进会话。语音因此可以不走频道，也就不需要开发参数。

### mod 怎么把一句话送进会话

卡片本身不和 Claude Code 说话。卡片只把声音交给桥接程序；真正把这句话放进会话的，是插件里的 mod。

mod 是插件里的一段 JavaScript 程序，Claude Code 每开一个会话，就在自己内部运行它。它能在固定时刻被叫醒，例如“会话开始”；也能调用 Claude Code 给它的功能。FunMedal 要用两个：`$.process.spawn` 启动一个小程序，并一直读它的输出；`$.prompt.submit({ text, asUser: true })` 往会话里放一句话，效果和你在输入框里打这句话再按回车一样。频道是从 Claude Code 外面往里推消息，所以要开发参数；mod 在 Claude Code 里面替你打字，所以不用。

```text
+------+  [1]  +--------+  [2]  +----------+  [3]  +-----+  [4]  +---------+
| card | ----> | bridge | ----> | listener | ----> | mod | ----> | session |
+------+       +---+----+       +----------+       +-----+       +---------+
   ^               |
   |      [5]      |
   +---------------+
```

图里 `card` 是卡片，`bridge` 是桥接程序，`listener` 是 mod 启动的、守着收话的小程序，`mod` 是插件里的 mod，`session` 是 Claude Code 会话。

准备：会话一开始，mod 被叫醒，用 `$.process.spawn` 启动 `listener`。`listener` 连上桥接程序，报上自己属于哪个 `claude` 进程。要这个小程序，是因为 mod 处理一次事件最多运行 10 秒，没法一直守着等你开口（见下文“走 mod 这条路要注意的事”第 1 条）。

1. 你按住卡片中间的键说话。卡片边录音边用蓝牙发给桥接程序，桥接程序用 macOS 自带的离线语音识别把声音转成文字，声音不出这台 Mac（`notes/voice.md` “整体流程”）。这一段现在就能用，不变。
2. 你松开键后，桥接程序选出最近需要你的那个会话，把文字发给那个会话的 `listener`。选法和现在一样（`notes/voice.md` “送进哪个会话”）。
3. `listener` 收到一句就输出一行。mod 在后台一直读它的输出，读到一行就拿到了这句话。
4. mod 调用 `$.prompt.submit`，把这句话当作你打的字送进会话。Claude 空闲时马上开始干活；正在干活或者批准框挂着时，这句话排队等着；按 Stop（停止 Claude 当前这一轮的按钮）时排队中的话会被丢掉，按过之后再送的话会被拒绝，要你先在电脑上亲手打一句话，见“按 Stop 之后丢话的复查”。
5. mod 拿到结果后，经 `listener` 告诉桥接程序，桥接程序再告诉卡片，卡片显示“已排队”“已送进去”或“没送进去”。

和现在比，只换了第 2 到第 4 步。现在是桥接程序把文字交给频道服务器（Claude Code 为每个会话启动的、负责推消息的子程序），再由频道推进会话。卡片、蓝牙和语音识别都不改。

已验证的：mod 能启动 `listener`，能把它输出的每一行当作你的话送进会话；排队和按 Stop 之后被拒绝也测过，见“mod 实验”和之后两节。实验里的 `listener` 读的是一个文本文件，不是桥接程序。还没做的：让 `listener` 改为连桥接程序；第 5 步把结果传回卡片。

### 推荐的组合（按先后）

多模型头脑风暴之后的修改版见下文“多模型头脑风暴”的“修改后的推荐组合”。

1. **插件：hooks 加 mod，不含频道。**
   - 一次性：运行一条命令 `claude plugin install funmedal --marketplace sixianli/FunMedal`。`sixianli/FunMedal` 是放插件的 GitHub 仓库，Claude Code 把它当作插件市场（可以从中安装插件的仓库）。这条命令要求 Claude Code v2.1.292 或更新，负责人的终端版正是 2.1.292。
   - 每天：0 步。mod 在会话开始时启动桥接程序，并把卡片上说的话当作你打的字送进会话。状态显示和按键批准继续由 hooks 完成。
2. **编译好的桥接 App，装在固定位置**（例如 `/Applications/FunMedalBridge.app`）。
   - 一次性：装 App；允许蓝牙、允许语音识别各一次。
   - 每天：0 步。
   - 自己用时，沿用现在的临时签名（只在本机有效的签名）就够了。要发给别人用，必须用 Developer ID（Apple 发给付费开发者的签名证书）签名并公证（交给 Apple 自动检查一遍），否则别人的 Mac 会拦下这个 App。
   - 负责人 2026-10-17 定：不发编译好的 App，开源以后也由使用者自己编译，不买 Apple 开发者会员（G14），见“修改后的推荐组合”第 3 条。
3. **不用 ESP-IDF 刷固件。**
   - 一次性：备份原厂固件，再刷编译好的固件文件。命令行方式只装 `esptool`；网页方式要用 Chrome 或 Edge。刷完照旧配对一次。
4. **只给旧版本用户的备用路：频道加短启动命令。** 只有 Claude Code 低于 v2.1.287 时才需要。负责人的终端版 2.1.292、桌面 App 自带的 2.1.295 都满足 mod 的版本要求（`notes/claude-code.md:14`），所以自己用时不需要这一步。负责人 2026-10-17 定：不留这条备用路，使用 FunMedal 前必须把 Claude Code 升级到最新版（G17）。

### 双方一致的地方

- 插件比改 `settings.json` 稳：卸载、升级、和你已有的 hooks 共存，都更干净。
- mod 比频道好：不需要开发参数；也不会出现“会话没有加载频道，卡片却显示已发送”的情况，FunMedal 之前把这种情况叫“假发送”。
- 跨会话消息和后台监视器都不适合当语音入口。
- 桥接程序放在插件外面的固定位置，不放进插件。
- 第 4 步配对已经够简单，不用改。

### 双方不同的地方，以及 Claude 的判断

1. **频道要不要继续维护。** OpenCode 认为要，给低版本的 Claude Code 当备用路。Claude 认为：负责人自己的两个版本都够用，备用路只在发给别人用时才需要，可以等决定发不发给别人时再定。负责人 2026-10-17 定：不留备用路，使用前必须把 Claude Code 升级到最新版（G17）。所以 mod 送语音做好之后，频道这条路删掉。
2. **“插件里直接带 App，每次插件升级都会重弹授权”**（OpenCode）：部分成立。macOS 按程序内容记住蓝牙和语音授权（`notes/bridge.md:113`），App 内容没变就不会重弹；但只要改了桥接程序的代码，就会重弹。所以放在插件外面仍然更好，结论不变。
3. **“跨会话消息在你人不在时正好会被扣住”**（OpenCode）：部分成立。只有接收消息的会话处在跳过所有权限确认的模式（bypassPermissions）时，消息才默认被扣住等你批准；在自动模式（Claude Code 自己判断哪些操作要你确认）等会弹确认的模式下，默认会送达（cross-session-messaging 的 “Control inbound messages”）。这不改变结论：跨会话消息到了 Claude 那里，会被标成“来自另一个会话，不是你说的”，不能当作你的指令。
4. **“网页上先备份、再刷固件”**（Claude 第一轮）：OpenCode 指出这一条写得太轻，成立。ESP Web Tools（常用的网页刷固件组件）不能把卡片里的内容读回来；要做网页备份，得用 esptool-js（乐鑫官方的 JavaScript 版刷写库，有 `readFlash` 读回功能）自己写页面。
5. **菜单栏 App 和桥接程序分成两个程序**（Claude 第一轮）：OpenCode 指出，蓝牙和语音授权跟着真正使用它们的程序走，分成两个程序就会有两套授权框。成立：要做菜单栏 App，就让桥接程序本身当菜单栏 App。

### 走 mod 这条路要注意的事

前 6 条是 OpenCode 第二轮补充的，Claude 已对照官方文档核对过；第 7、8 条是 Claude 核对时补的。

1. **10 秒限制。** mod 处理一个事件最多运行 10 秒（等待 mods 接口调用的时间不算）。所以听卡片的语音，要用 `$.process.spawn` 启动一个一直运行的小程序，不能在处理事件时一直等着。
2. **Claude 在忙时，语音要排队。** `$.prompt.submit` 会等会话空闲才开始新一轮。Claude 正在干活、或者正停在批准框上时要等多久，文档没写。卡片必须分清“已排队”和“已送进去”，否则又成了假发送。终端实验测到：Claude 在干活时，等这一轮结束才进去；批准框挂着时，等批准框被回答才进去，见“mod 实验”。
3. **mod 会被关掉。** 用 `--safe-mode`（关掉所有自定义的安全模式）启动、在设置里写 `"disableAllHooks": true`、或者公司用 `allowManagedModsOnly` 限制时，mod 不加载，语音也就不能用。这时卡片应该显示“没有能接收的会话”。前两种情况下 hooks 也一起停（`disableAllHooks` 关掉全部 hooks，见 hooks 文档 “Disable or remove hooks”），状态显示和按键批准也不能用，卡片整张不工作；这一点是多模型头脑风暴时 DeepSeek 指出的。
4. **会话记录里看不出这句话来自语音**（OpenCode 提出）：实验推翻了。终端会在这句话上方显示它来自哪个插件，会话记录里这条消息也带着插件名，见“mod 实验”。
5. **别的 mod 能改写或拦下语音。** mod 听语音靠 `$.process.spawn` 启动的小程序，而任何 mod 都能拦截 `process.spawn`：别的插件启动的程序每输出一段，它都先看到，还能改掉再往下传（本机接口说明 `index.d.ts` 里的例子是把输出里的密钥换成 `***`）。装了这样的 mod，卡片说的话可能被改写，或者送不进去；后一种是从写法推断的，没测过。公司能通过统一管理的设置（管理员推到员工电脑上、员工自己改不了的配置）给员工电脑装 mod；在自己的电脑上，只有你自己装的插件会这样做。对 FunMedal 影响很小，留作提醒。
6. **版本要求。** mod 在终端要 v2.1.287 或更新，桌面 App 自带的 Claude Code 要 v2.1.286 或更新；从终端一条命令装插件要 v2.1.292。负责人 2026-10-17 定：使用 FunMedal 前必须把 Claude Code 升级到最新版，不留旧版本的备用路（G17）。做法：说明里写“先升级到最新版”；插件和 `doctor`（以后要做的排查命令，见“修改后的推荐组合”第 6 条）只拦下低于 v2.1.292 的版本并提示升级，不拿“是不是最新版”当硬性检查，否则 Claude Code 每发一个新版，没来得及升级的人都会被拦下。
7. **桌面 App 里也能用语音。** 文档写明 mod 在桌面 App 的 Code 标签页里运行；而频道加开发参数的方式在桌面 App 里能不能用，还没验证过（`notes/claude-code.md:139`）。如果实验成功，按住说话就能用在桌面 App 的会话里，这是现在做不到的。

## mod 实验

2026-10-17 在终端里做了一次 mod 实验（任务条目 OB-2），回答上面“还没确认的事”的第 1、2 条。实验没有碰卡片，也没有改用户设置。桌面 App 部分（OB-3）见下一节“桌面 App 里的 mod 实验”。

### 怎么做的

- 实验插件在 `experiments/mod-submit/plugin/`。它的 mod（`hooks/register.js`）在会话开始时用 `$.process.spawn` 启动一个一直运行的小程序；小程序逐行读一个“收件文件”，每读到一行，mod 就用 `$.prompt.submit({ text, asUser: true })` 把这行字当作用户的话送进会话。将来正式做时，把收件文件换成和桥接程序的连接，桥接程序收到卡片上说的话、转成文字后发过来。
- 驱动脚本 `experiments/mod-submit/run.py` 在伪终端（让程序以为自己运行在真终端里的系统机制）里启动真正的 Claude Code 交互会话，用 Haiku 模型，权限模式是每次都问（`--permission-mode default`）。它按顺序制造几种情况，每种情况往收件文件写一句话，再用 hooks 和 mod 自己记下的时间，判断这句话什么时候进入会话。
- 文档写明的行为，脚本会判断对错，不符合就以退出码 1 结束；文档没写的行为只记录。
- 一次运行约 6 分钟，开两个 Claude Code 会话，一共发 6 句短话，用量很小。

### 对设计的影响

- **卡片要分两步显示。** 话交给 mod 以后显示“已排队”；`$.prompt.submit` 返回（也就是新一轮真正开始）以后再显示“已送进去”。会话空闲时两者相差不到 1 秒。
- **语音不会打断 Claude。** Claude 在干活时说的话，要等这一轮做完才进去，卡片要一直显示“已排队”，直到真正进去。
- **批准框挂着时说的话，要等批准框被回答才进去。** 用卡片按键回答批准框后，排队的那句话紧接着进去。
- 这些只在终端里测过，权限模式是每次都问。负责人平时用的自动模式没有测。桌面 App 里前三条一样，但按过 Stop 之后不一样，见下一节。

## 按 Stop 之后丢话的复查

2026-10-17 20:03–20:43（东京时间）在桌面 App 里又做了一次（任务条目 OB-5），回答上一节“还没确认的”第 1 条：按 Stop 之后为什么丢话，怎样恢复。负责人同意了再临时改一次设置（`.agents/tasks/onboarding/goal.md` 的 G11）。实验没有碰卡片。

结论：

1. **丢话是 Claude Code 引擎自己的规则，不是故障，也不是桌面 App 加的 hook。** 按 Stop 时，引擎把队列里由插件送来、还没执行的话删掉，并记下“这个会话被停过”。之后插件送的话一律被拒绝，直到用户亲手输入一句话。例如：Claude 干活时你在电脑上按了停止，走开后按住卡片说“接着跑测试”，这句话送不进去；你回到电脑前，在这个会话的输入框里打一句“继续”发出去，之后卡片说的话又能进去。
2. **用户在输入框里亲手发一句话，就恢复了。** 从另一个会话发来的消息不算，发来之后 mod 送的话仍被拒绝。
3. **桌面 App 里的 `/clear`（清空对话）会结束这个会话的整个 Claude Code 进程。** mod 和它读收件文件的小程序一起结束。App 要等下一条消息来了才启动新进程，只切到这个会话不会启动。新进程里 mod 送的话能进去。
4. **新开的会话能进去。**

两种理由的意思：

- `the prompt was removed from the queue before it ran`：这句话还在排队，没轮到执行就被删掉了。

### 原因：Claude Code 引擎里的一条规则

下面的依据来自读程序文件，属于静态证据，官方文档里没有写。

- **桌面 App 自带的 Claude Code 2.1.299 程序文件里有这条规则。** 第二种理由的原文就在里面，旁边的代码做三件事：
  - 按 Stop 时，记下哪个会话、什么时候被停止，并把队列里来源是插件的话删掉。
  - 插件再送话时，如果这个会话被停止过，就拒绝。
  - 只有这次送话背后有一次用户在 Stop 之后亲手做的操作，才解除。代码里这个时间叫 `vouchedPressAt`。从名字和它的来源（一个叫 `gestureAt` 的值）推断，它指用户按下插件画在 Claude Code 界面上的按钮的时间；这一点没有实测。
- **这条规则受一个开关控制。** 开关名是 `tengu_plugin_input_refusal`，代码里的默认值是打开。看写法，它是 Claude Code 用来决定某项功能开不开的那类开关；它能不能不发新版本就被改掉，没有查证。
- **本机生成的接口说明 `index.d.ts` 没有写这条规则。** 它只说 `drop` 表示“hook 拒绝了，或设置里的 hook 挡住了”。
- **用户打字能解除，来自上表的实测。** 代码里解除这个状态的具体位置没有找到。
- **终端里的 Claude Code 2.1.292 没有这条规则。** 它的程序文件里搜不到第二种理由的原文，也搜不到开关名。同一块代码里的另外两句理由（包括第一种理由）能搜到，说明搜索方法对这个文件有效。所以按程序文件看，终端现在的版本还没有这条规则，它是 2.1.292 之后才加的；终端实验也没有测过“打断之后再送”。终端升级以后是否一样，见下文“还没确认的”第 1 条。

### 对设计的影响

- **不能绕开，也不该绕开。** 从代码看，这条规则的用意是：用户按了停止，插件就不能自己让 Claude 接着干活。卡片上的按键是实体按键，不是 Claude Code 界面上的按钮，引擎认不出“这是用户按的”。所以按过 Stop 之后，卡片说的话送不进去，直到用户在电脑上打一句话。能不能让 mod 在桌面 App 的界面上画一个按钮、让用户点一下来解除，没有查清：会话开始时 `$.session.surfaces()` 返回空列表，但界面可以之后再登记到会话上，之后能不能画没测过；“点插件画的按钮能解除”本身也只是从代码推断的。即使能画，用户也要在电脑前点，只是把打一句话换成点一下。
- **卡片的“没送进去”要分两种提示。** mod 能从 `drop` 的文字分出两种情况：排队中被删掉时，提示“刚才那句被停止清掉了，请再说一遍”；停过之后被拒绝时，提示“你按过停止，请先在电脑上打一句话”。
- **桌面 App 里 `/clear` 之后，语音要重新连上。** 清空对话会结束整个 Claude Code 进程，mod 和桥接程序的连接跟着断开。App 要等用户发来下一条消息才启动新进程，卡片说的话启动不了它。所以桥接程序要能发现连接断了，卡片显示“未连接”，等新进程里的 mod 重新连上再恢复。终端里 `/clear` 不结束进程，不受影响。官方命令文档说 `/clear` 是开一段新对话、清空上下文（commands 页 `/clear` 一行），没有要求重启程序；终端照此只清空对话，结束整个进程是桌面 App 自己的做法，文档没写原因。
- **推荐组合第 2 条“mod 送语音”仍然可用。** 平常的情况都能送；按过 Stop 或在桌面 App 里清空对话之后，用户在电脑上打一句话就恢复。

### 核对后否定或更正的说法

1. **否定：“由插件在会话开始时启动的桥接程序，会话结束时会跟着结束，人走开后卡片就不显示状态了”**（DeepSeek 第二轮认为这条最要紧；GLM 第二轮也以为桥接程序随会话起止）。桥接程序必须用 `open` 启动（`notes/bridge.md:40`），`open` 交给 macOS 自己启动这个 App，它不是会话的子进程。2026-10-17 18:28 查本机正在运行的桥接程序：它是用 `open -g` 启动的，父进程号是 1（`launchd`，macOS 负责启动和看管程序的系统进程），已经运行了 1 小时 43 分钟。实验里“跟着会话结束”的，是 mod 用 `$.process.spawn` 启动的听语音小程序，它本来就该跟着会话走。要记住的只有一点：写插件时，桥接程序要用 `open` 启动，不能用 `$.process.spawn`。
2. **否定：“hooks 被关掉时，用 `claude agents --json` 代替状态显示”**（DeepSeek）。`claude agents --json` 是列出后台会话状态的命令。文档写明，在别的终端里正常打开的交互会话不在这个列表里，转到后台之后才会出现（agent-view “Monitor sessions with agent view”）。负责人平时用的会话都不在列表里，所以它代替不了 hooks。
3. **确认，并改了上文：“mod 被关掉时，不只是语音不能用”**（DeepSeek）。`disableAllHooks` 关掉全部 hooks（hooks 文档 “Disable or remove hooks”），`--safe-mode` 关掉所有自定义，状态显示和按键批准也一起停。上文“走 mod 这条路要注意的事”第 3 条已补上。`doctor` 要能查出这种情况。
4. **部分成立：“`notes/bridge.md:113` 说 macOS 按程序内容记授权，不准确”**（DeepSeek）。对临时签名，这句话是对的：TN3127 写明临时签名的认定规则只对应那一版。它没说出的是一般规则：macOS 记的是认定规则，所以换成证书签名就能保住授权。`bridge.md` 不改，一般规则写在本节。
5. **部分成立：“`asUser: true` 不带署名”的说法要分开写**（GLM）。文档说的是：Claude 读到的内容里没有“这句话来自某个 mod”的说明，Claude 把它当成你的话。实验看到的是：终端和会话记录里仍标着插件名。两件事都对，上文“核对过的事实”表已改成分开写。
6. **更正：`notes/claude-code.md:38` 已过时**（MiMo）。那里写“往已经在运行的会话里塞消息，官方文档里只有 Channels”；现在还有 mod 的 `$.prompt.submit`，已在该行补上。

### 修改后的推荐组合

1. **Claude Code 这一侧：插件，含 hooks 和 mod，不含频道。**
   - 自己用：用本机仓库目录添加插件市场，再从中装插件，一次性两条命令。之后改插件代码，下一个会话自动生效。（在原方案“从 GitHub 装”的基础上改，来自 GLM 第一轮）
   - 发给别人：照原方案从 GitHub 的插件市场装，并写清升级步骤（GLM）。
   - 卸载：一条命令卸掉插件，并提示退出桥接程序、在蓝牙设置里忽略卡片（DeepSeek）。
   - 每天：0 步。
   - 使用前：把 Claude Code 升级到最新版，不留旧版本的备用路（负责人 2026-10-17 定，G17）。
2. **对接**：hooks 管状态和按键批准；mod 用 `$.prompt.submit({ text, asUser: true })` 送语音；卡片和终端都分“已排队 / 已送进去”两步显示，终端用 `$.ui.status`（DeepSeek）。桌面 App 实验之后，再加第三种“没送进去”，见“桌面 App 里的 mod 实验”；“没送进去”分两种提示，桌面 App 里清空对话之后还要显示“未连接”，见“按 Stop 之后丢话的复查”。不用跨会话消息，也不用 `claude agents --json`。频道这条路在 mod 送语音做好之后删掉（G17）。
3. **桥接程序**：使用者自己运行 `mac/bridge/build.sh` 编译，装到固定位置；不发编译好的 App，也不用 Developer ID 签名（负责人 2026-10-17 定，开源以后也一样，G14）；会话开始时由插件用 `open -g` 启动，已经在跑时新启动的会自己退出（`notes/bridge.md` “怎么配置”第 3 步）；用固定证书签名（三个模型，用哪种证书由负责人定）；一启动就请求语音权限（DeepSeek）；会话开始时发现它没在跑就提示（MiMo）。登录时自动启动仍是可选项。
4. **固件**：两种都给：发编译好的固件文件，同时保留源码，想自己编译的照旧用 ESP-IDF（负责人 2026-10-17 定，G15）。先做一条本地命令，只需装 `esptool`，命令里依次备份、校验、刷写（MiMo、DeepSeek）。网页方式等在真卡片上测过读回 8 MB 再定。固件和桥接程序连上时互报版本（MiMo）。
5. **配对**：第一次配对不改。失败或取消时，桥接程序自动重连、再弹配对框（MiMo）。说明里写清“附近有两张卡”和“换回原厂后要先忽略卡片”这两种情况（DeepSeek）。
6. **排查**：`funmedal-bridge doctor` 一条命令依次查：桥接程序在不在跑；蓝牙和语音是否允许；签名是临时签名还是证书；卡片连没连上、固件版本配不配；插件是否装上、是否被 `disableAllHooks` 关掉（三个模型）。
