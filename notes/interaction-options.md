# 交互方案

卡片的条件：240×320 竖屏彩色屏（分辨率是推断，见 [hardware.md](hardware.md)），3 个功能键（上、确认、下），有喇叭，很可能有麦克风，有电池。下面几个方案只决定“看起来什么样、按键怎么用”，背后的数据都一样：Claude Code 的会话状态、等待批准的请求、iPhone 和 Mac 的通知。

## 所有方案共用的规则

- **三个键的固定分工**：确认键 = 做主要的事（批准、打开）；上键 = 保守的事（拒绝、稍后）；下键 = 翻看（下一条、详情）。每个方案都在屏幕底部标出当前三个键的作用，不用记。
- **长按确认键说话**：按住录音，松开发送，像对讲机一样（要等麦克风确认后才能做）。
- **声音提示**：要你批准时响一声上扬的音，任务做完响一声短促的音，出错响一声低音。可以静音。
- **多个会话**：每个会话用项目名（工作目录的文件夹名）区分。
- **省电**：没有新事件时屏幕变暗，有事件时亮起。

## 方案

### A 像素小伙伴

屏幕中间是一个像素小人，它的动作就是 Claude Code 的状态：工作时敲键盘，等批准时举牌、跳动，做完了庆祝，出错了晕倒。通知由小人“送信”进来，右上角显示未读数。可以加养成元素，比如小人随着完成的任务变多而长大。

- 好处：最有趣，最有“桌面伙伴”的感觉，一眼就能看出状态。
- 代价：要画动画素材；同时有好几个会话时，一个小人表达不完，需要切换。

### B 航班信息屏

模仿机场的翻牌式出发屏。每个会话占一行：等批准 = BOARDING（登机中），工作中 = IN FLIGHT（飞行中），完成 = LANDED（已降落），出错 = DELAYED（延误）。下半部分是“到达”栏，按 App 汇总通知数。状态变化时字牌翻动，配哗啦声。

- 好处：同时看多个会话最清楚，复古又好认。
- 代价：通知只能看到汇总，要按进去才看内容。

### C 卡牌堆

每个需要你处理的东西（权限请求、通知）都变成一张牌，叠成一摞。上键 = 稍后（放到底下），确认键 = 处理（批准或打开），下键 = 划走（拒绝或忽略）。新牌进来时有发牌动画，重要程度用边框颜色区分。

- 好处：三个键处理事情最快，最适合“批准 / 拒绝”和清通知。
- 代价：只能看到当前要处理的事，看不到整体状态。

### D 复古终端

绿色荧光字的终端界面，把 Claude 正在做的事压缩成一行行日志滚动显示；要批准时像命令行一样出现 `[Y/n]`；通知以系统消息的样子逐字打出来，配键盘咔哒声。

- 好处：程序员最有认同感，信息量最大。
- 代价：字小、信息密，离远了看不清；趣味来自风格，不来自互动。

### 可以混搭

这几个方案可以组合，比如平时显示 A 或 B 当主页，一有要处理的事就弹出 C 的卡牌，处理完再回到主页。我推荐 **A 当主页 + C 处理事情**：A 让它有趣、愿意放在桌上，C 让三个键处理事情最快。
