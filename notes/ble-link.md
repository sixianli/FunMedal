# 卡片和 Mac 之间的蓝牙连接

本文记录 2026-10-16 实测的卡片和 Mac 之间的低功耗蓝牙（BLE，一种省电的蓝牙，手环、耳机常用）传输能力，用来决定两件事：语音能不能走蓝牙，按键反应快不快。原始数据在 [experiments/ble-throughput/results/](../experiments/ble-throughput/results/)。

## 结论

| 问题 | 结果 | 依据 |
| --- | --- | --- |
| 卡片 → Mac 能持续传多快 | 6 轮每轮 5 秒，最慢 309 kbps（千比特每秒），中位数 389 kbps，最快 421 kbps | 实测，Mac 端按收到的数据计时 |
| Mac → 卡片能持续传多快 | 6 轮，最慢 253 kbps，中位数 419 kbps，最快 452 kbps | 实测，卡片端按收到的数据计时 |
| 会不会丢数据 | 两个方向共 5,934 个数据包，按编号核对，一个没丢、没有乱序 | 实测 |
| 按键反应快不快 | Mac 发一个小包、卡片原样送回，来回一趟中位数 22 ms（毫秒），90% 在 36 ms 以内，60 次里最慢 53 ms。单程大约是一半 | 实测 |
| 语音能不能走蓝牙 | 能。语音压缩成 ADPCM（一种简单的音频压缩，把每个采样从 16 位压到 4 位）后只要 64 kbps，约占最慢一轮的 21% | 用实测最慢值推算 |
| 不压缩的原始语音能不能走 | 勉强。原始 PCM（未压缩的音频采样）要 256 kbps，占最慢一轮的 83%，余量太小，不建议 | 用实测最慢值推算 |

## 实测结果

### 测试条件

- **Mac**：MacBook Air，macOS 27.2（26B5086k）。
- **卡片**：烧了专门测速的固件（烧在芯片里的程序；这一份只做蓝牙收发，不点亮屏幕），用 ESP-IDF v5.5.5（乐鑫官方开发环境）里的 NimBLE（ESP-IDF 自带的一套蓝牙软件）编写。
- **距离**：卡片在 Mac 旁边，信号强度 RSSI（接收到的信号强弱，数值越接近 0 越强）为 −43 dBm（信号强度的单位），属于很强的信号。
- **其他**：连接没有加密；Mac 的 Wi-Fi 没有关，也没有控制它的流量。

### 双方商定的连接参数

蓝牙连上以后，双方会商定几项决定速度的参数。实测商定结果如下：

| 参数 | 是什么 | 实测值 |
| --- | --- | --- |
| 连接间隔 | 双方每隔多久碰一次头交换数据 | 15 ms。这是 macOS 自己选的；卡片再请求 15 ms，macOS 也同意了 |
| ATT MTU | 一次能发的最大数据块 | 517 字节。卡片每包实际能装 514 字节，Mac 每次最多能写 512 字节 |
| PHY | 无线信号的调制速率 | 两个方向都是 2M（高速模式，空中每秒最多传 200 万位） |
| 链路层数据长度 | 空中每个小包最多装多少字节 | 两个方向都是 251 字节、最长 2120 微秒 |
| 监督超时 | 多久收不到对方就算断线 | macOS 默认 360 ms；卡片请求后变成 4 秒 |

### 速度

每轮持续 5 秒。前 3 轮用 macOS 默认的参数；后 3 轮先由卡片请求 15 ms 连接间隔、4 秒监督超时，再测。

| 轮次 | 卡片 → Mac（kbps） | Mac → 卡片（kbps） |
| --- | --- | --- |
| 默认参数 1 | 391 | 426 |
| 默认参数 2 | 403 | 412 |
| 默认参数 3 | 421 | 443 |
| 卡片请求后 1 | 385 | 406 |
| 卡片请求后 2 | 388 | 452 |
| 卡片请求后 3 | 309 | 253 |

- 卡片请求前后，连接间隔都是 15 ms，速度没有明显差别。最后一轮两个方向都变慢，原因没查（可能是 Wi-Fi 干扰，未确认）。
- 卡片发送时，每一轮都有大约 5,000 次“缓冲区满了、等 1 ms 再发”。这说明卡片一直在等蓝牙链路腾出空间，速度卡在链路上，不是卡片程序发得慢。这是根据计数推断的。

### 来回一趟的时间

Mac 往卡片发一个 13 字节的小包，卡片收到后马上原样送回；Mac 收到回声后隔 37 ms 再发下一个。每组 30 次，共两组：

| 参数 | 最快 | 中位数 | 90% 以内 | 最慢 | 丢失 |
| --- | --- | --- | --- | --- | --- |
| 默认参数 | 21.4 ms | 22.1 ms | 34.3 ms | 52.8 ms | 0 |
| 卡片请求后 | 20.4 ms | 22.2 ms | 36.4 ms | 39.4 ms | 0 |

按下卡片上的键到 Mac 收到，大约是来回一趟的一半，中位数约 11 ms，人感觉不到。

## 对设计的影响

1. **语音走蓝牙，不需要 Wi-Fi**：卡片录音后压缩成 ADPCM，用 64 kbps 发给 Mac，由 Mac 转成文字。蓝牙和 iPhone 通知可以共用一条无线，不用另外配 Wi-Fi 密码。
2. **按键直接走蓝牙**：反应时间远低于人能察觉的程度，不需要额外优化。
3. **平时要换省电参数**：本次测的是最快的参数（15 ms 碰一次头、不允许跳过）。平时卡片只需要收状态、发按键，应该请求更长的连接间隔，或者允许卡片跳过几次碰头，录音时再切回快速参数。macOS 接受哪些参数、能省多少电，还没测。
4. **Mac 端程序必须是独立 App**：从 Claude 里直接运行用蓝牙的命令行程序，会被 macOS 结束。原因是系统把它算在启动它的 claude 名下，而 claude 没有声明要用蓝牙。测速程序因此打包成了带蓝牙用途说明的 `.app`（Mac 的应用程序包），由用户用 `open`（macOS 打开应用的命令）启动。正式的 Mac 端常驻程序也要这样做。

## 没有测到的

- 距离远一点或隔着东西时的速度，比如卡片放在两米外、Mac 合盖。
- 加密配对以后的速度。加密会让每个小包多带 4 字节校验码，影响应该很小，未确认。
- 卡片同时连着 iPhone（收通知）时，和 Mac 之间的速度。
- Mac 的 Wi-Fi 在大量传数据时的干扰。
- 耗电。
- 长时间连续传输（本次每轮只有 5 秒）、Mac 睡眠或锁屏后连接会不会断。

## 测速程序怎么工作

卡片上开了一个蓝牙服务，里面有三个“特征值”（蓝牙里用来读写数据的小格子）：

| 名字 | 方向 | 用途 |
| --- | --- | --- |
| TX（`6d2f0002-…`） | 卡片 → Mac，用“通知”（卡片主动推送，不等对方确认） | 推测速数据，每包开头是 `D` 加 4 字节编号；回声包以 `E` 开头；每轮结束发 `F` 加一段统计 |
| RX（`6d2f0003-…`） | Mac → 卡片，用“无响应写入”（Mac 只管写，不等卡片确认） | Mac 写测速数据，每包开头是 4 字节编号，卡片统计字节数和丢包 |
| CTRL（`6d2f0004-…`） | 双向 | 写 `S`+秒数开始推送；写 `Z` 清零接收统计；写 `E`+数据要求原样送回；写 `C`+两个数请求连接间隔；写 `P`+数要求换 PHY；读它拿到一段统计和连接参数 |

服务编号是 `6d2f0001-6b0e-4a8e-9a4b-46756e4d6564`，卡片对外广播（让附近设备能搜到它）的名字是 `FunMedal-Bench`。

## 怎么重跑

1. 卡片醒着时编译并烧录测速固件（会覆盖卡片上原有的程序，原厂固件可以用 `firmware-backup/` 里的备份恢复）：

   ```bash
   export IDF_TOOLS_PATH=$HOME/esp/.espressif && . $HOME/esp/esp-idf-v5.5.5/export.sh && cd experiments/ble-throughput/firmware && idf.py -p /dev/cu.usbmodem11301 build flash
   ```

2. 编译 Mac 端测速 App：`experiments/ble-throughput/mac/build.sh`。
3. 想留卡片日志的话，在 `experiments/ble-throughput/` 下先运行 `python serial_log.py /dev/cu.usbmodem11301 600 results/<名字>-card-serial.log`，它从 USB 串口（卡片输出文字日志的通道）读日志，需要装了 pyserial（Python 读串口的库）的 Python。
4. 在自己的终端运行下面的命令（第一次运行要在弹窗里允许它用蓝牙）。可选参数有 `--seconds`（每轮秒数）、`--rounds`（轮数）、`--echoes`（回声次数）：

   ```bash
   open -W -n --stderr "$PWD/experiments/ble-throughput/results/<名字>-mac.stderr" experiments/ble-throughput/mac/build/FunMedalBench.app --args --out "$PWD/experiments/ble-throughput/results/<名字>-mac.json"
   ```
